# SELSP 数据库详细设计

## 1. 文档定位

本文档用于记录 `SELSP` 工程当前数据库结构、字段定义、约束、初始化数据和维护约定。

配套结构化工作簿：

- `doc/aip接口文档/用户api/SELSP_数据库设计文档.xlsx`

适用范围：

- `src/main/resources/schema.sql`
- `src/main/resources/data.sql`
- 后续新增表、删改字段、调整约束、修正初始化数据的场景
- 配套规则文档：`doc/rule/数据变更同步规则.md`

## 2. 维护规则

只要发生以下任一变更，必须同步修正文档：

- 新增表、删除表、重命名表
- 新增字段、删除字段、修改字段类型、长度、默认值、非空约束
- 新增、删除、修改主键、唯一键、索引、外键或检查约束
- 新增初始化数据、删除初始化数据、修正初始化数据内容或写入策略

同步修正时至少更新：

- 表结构定义
- 字段说明
- 约束说明
- 初始化数据说明
- 变更记录

禁止出现以下情况：

- `schema.sql` 已变更，但文档仍保留旧字段或旧约束
- `data.sql` 已变更，但文档未更新初始化数据说明
- 文档只写表名，不写字段业务含义和约束

## 3. 数据源概览

- 数据库类型：`H2`
- 运行方式：内存库
- JDBC URL：`jdbc:h2:mem:selsp;MODE=MYSQL;DB_CLOSE_DELAY=-1;DB_CLOSE_ON_EXIT=FALSE`
- 主配置文件：`src/main/resources/application.properties`
- 表结构脚本：`src/main/resources/schema.sql`
- 初始化数据脚本：`src/main/resources/data.sql`

## 4. 表设计

### 4.1 `sys_user`

表用途：

- 承接用户 API 模块的最小用户数据存储
- 支撑用户新增、修改、删除、查询和初始化数据验证

主键策略：

- 主键字段：`id`
- 生成方式：`BIGINT GENERATED BY DEFAULT AS IDENTITY`
- 说明：由数据库自增生成，业务代码不得手工指定运行时主键

唯一约束：

- `uk_sys_user_email`
  说明：限制用户邮箱唯一，避免重复账号数据

字段定义：

| 字段名 | 类型 | 非空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| `id` | `BIGINT` | 是 | 数据库自增 | 用户主键 |
| `name` | `VARCHAR(100)` | 是 | 无 | 用户显示名称 |
| `email` | `VARCHAR(150)` | 是 | 无 | 用户邮箱，系统内唯一 |
| `status` | `VARCHAR(32)` | 是 | 无 | 用户状态，如 `ACTIVE` |
| `created_at` | `TIMESTAMP` | 是 | `CURRENT_TIMESTAMP` | 创建时间 |
| `updated_at` | `TIMESTAMP` | 是 | `CURRENT_TIMESTAMP` | 更新时间 |

当前 DDL：

```sql
CREATE TABLE IF NOT EXISTS sys_user (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(150) NOT NULL,
    status VARCHAR(32) NOT NULL,
    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP,
    CONSTRAINT uk_sys_user_email UNIQUE (email)
);
```

## 5. 初始化数据设计

初始化数据目标：

- 提供最小可用测试数据
- 支撑 `UserControllerTest` 的列表和新增主路径验证

当前初始化策略：

- 使用 `MERGE INTO` 按 `email` 幂等写入
- 避免测试和应用初始化多次执行时触发唯一键冲突

当前初始化数据：

| 邮箱 | 名称 | 状态 | 说明 |
| --- | --- | --- | --- |
| `test@selfsp.local` | `测试用户` | `ACTIVE` | 默认种子用户，用于接口测试 |

当前 DML：

```sql
MERGE INTO sys_user (email, name, status, created_at, updated_at)
KEY (email)
VALUES ('test@selfsp.local', '测试用户', 'ACTIVE', CURRENT_TIMESTAMP, CURRENT_TIMESTAMP);
```

## 7. 变更检查清单

每次改数据库相关内容时，提交前至少自检以下项目：

1. `schema.sql` 是否和本文档中的表结构、字段、约束一致。
2. `data.sql` 是否和本文档中的初始化数据说明一致。
3. `UserDao.xml`、`User.java`、`UserServiceImpl.java` 是否同步反映字段和约束变化。
4. 若新增或修正数据，本文档“初始化数据设计”与“变更记录”是否已同步更新。
5. 相关测试是否已覆盖受影响主路径。
